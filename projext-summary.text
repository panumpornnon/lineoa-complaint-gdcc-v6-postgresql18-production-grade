- แยกข้อความแจ้งผู้ใช้ตามสาเหตุที่เซสชันสิ้นสุด ได้แก่ ถูกแทนที่ด้วยการเข้าสู่ระบบจากอุปกรณ์อื่น บัญชีถูกปิดใช้งาน ผู้ดูแลสั่งให้ออกจากระบบ เซสชันหมดอายุ และกรณีที่ไม่พบเซสชัน โดยส่งรหัสเหตุผลผ่านฟิลด์ sessionReason ในคำตอบข้อผิดพลาด แทนการแสดงข้อความกลางๆ ว่าเซสชันหมดอายุซึ่งทำให้ผู้ใช้ไม่รู้ว่าเกิดอะไรขึ้น
- token ที่ออกก่อนมีระบบนี้จะไม่มีรหัสเซสชันอยู่ภายใน จึงใช้งานต่อไม่ได้และผู้ใช้ต้องเข้าสู่ระบบใหม่ทุกคน เป็นพฤติกรรมที่ตั้งใจ เพราะ token ชุดเก่าเพิกถอนไม่ได้ จะปล่อยให้ใช้ต่อก็เท่ากับยังมีช่องโหว่ค้างอยู่ในระบบ
- ฝั่งหน้าเว็บ ปรับให้เมื่อได้รับสถานะ 401 ที่มีรหัสเหตุผลแนบมา จะเด้งกลับหน้าเข้าสู่ระบบพร้อมแสดงข้อความอธิบายสาเหตุ และเมื่อเข้าสู่ระบบสำเร็จโดยมีเครื่องอื่นถูกดีดออก จะขึ้นข้อความแจ้งให้ทราบ พร้อมเพิ่มสไตล์ alert ระดับเตือนสีเหลืองอำพันใน admin-v3.css เนื่องจากเดิมมีเพียงสีแดงสำหรับข้อผิดพลาดและสีเขียวสำหรับความสำเร็จ
- ปรับสิทธิ์ของ role admin ให้เท่ากับ dev ในส่วนการจัดการทำเนียบเจ้าหน้าที่ ตามที่กำหนดว่า admin เป็นตำแหน่งรองจาก superadmin และควรทำได้เหมือนกัน โดยเปลี่ยนเส้นทาง governance staff-profiles ทั้งสี่เส้นทางจากที่อนุญาตเฉพาะ dev เป็นอนุญาต admin ด้วย และแก้เงื่อนไขฝั่งหน้าเว็บแปดจุดที่เดิมตรวจว่าสิทธิ์เป็น dev เท่านั้น
- ยังคงกฎที่ว่า admin แก้ไขหรือลบบัญชีที่มีสิทธิ์ dev ไม่ได้ไว้ตามเดิม เนื่องจากเป็นคนละเรื่องกับการเข้าถึงฟีเจอร์ หากเปิดให้ทำได้ ผู้ที่มีสิทธิ์ admin จะสามารถเลื่อนตนเองขึ้นเป็น dev หรือลบบัญชีสูงสุดของระบบทิ้งได้ ซึ่งเป็นการตัดสินใจด้านความปลอดภัยที่ต้องให้ผู้ดูแลระบบเป็นผู้กำหนด
- ปรับเวอร์ชัน admin.js และ admin-v3.css เป็น 20260924-single-session-1 เพื่อป้องกันเบราว์เซอร์ใช้แคชเก่า
- เพิ่มชุดข้อมูลบัญชีผู้ใช้งานในแท็บ นำเข้า / ส่งออก ให้ส่งออกและนำเข้าเป็นไฟล์ CSV ได้เช่นเดียวกับหน่วยงาน หมวดหมู่ และทำเนียบเจ้าหน้าที่ เพื่อให้เพิ่มบัญชีเจ้าหน้าที่ครั้งละหลายสิบคนได้โดยไม่ต้องกรอกทีละคนผ่านหน้าจอ
- ไฟล์ที่ส่งออกประกอบด้วยชื่อผู้ใช้ ชื่อที่แสดง สิทธิ์ รหัสหน่วยงาน สถานะการใช้งาน และเวลาเข้าสู่ระบบล่าสุด พร้อมคอลัมน์รหัสผ่านที่เว้นว่างไว้เสมอ ไม่มีการส่งออกค่า password_hash ออกจากฐานข้อมูลไม่ว่ารูปแบบใด คอลัมน์รหัสผ่านมีไว้ให้กรอกตอนเพิ่มบัญชีใหม่เท่านั้น ทำให้ไฟล์ที่ส่งออกนำกลับเข้ามาได้ทันทีโดยไม่ต้องเพิ่มคอลัมน์เอง
- บัญชีที่เพิ่มใหม่โดยไม่ได้ระบุรหัสผ่านในไฟล์ ระบบจะสร้างรหัสผ่านชั่วคราวยาวสิบหกตัวอักษรให้ด้วยตัวสร้างเลขสุ่มเชิงรหัสลับ และตัดตัวอักษรที่อ่านแล้วสับสนอย่าง O ศูนย์ I L และหนึ่งออก เพราะต้องอ่านบอกเจ้าหน้าที่ทางโทรศัพท์ได้ รหัสผ่านชุดนี้แสดงบนหน้าจอครั้งเดียวหลังนำเข้าสำเร็จ ไม่ได้บันทึกไว้ที่ใด ไม่ได้เขียนลงบันทึกการตรวจสอบ และเรียกดูย้อนหลังไม่ได้
- ไม่ส่งรหัสผ่านที่ผู้ใช้กรอกมาในไฟล์กลับไปแสดงในตารางตัวอย่าง แสดงเป็นข้อความว่าจะตั้งรหัสผ่านใหม่แทน เพื่อไม่ให้รหัสผ่านปรากฏบนหน้าจอโดยไม่จำเป็น
- การนำเข้าไม่อนุญาตให้สร้างหรือแก้ไขบัญชีที่มีสิทธิ์ DEV ด้วยเหตุผลเดียวกับหน้าจัดการผู้ใช้งาน คือการนำเข้าไฟล์ต้องไม่กลายเป็นช่องทางอ้อมให้ตั้งบัญชีสิทธิ์สูงสุดโดยข้ามการตรวจสอบ สิทธิ์ที่นำเข้าได้จึงมีสี่ระดับคือ officer supervisor executive และ admin
- กันไม่ให้ผู้ที่กำลังนำเข้าไฟล์ปิดใช้งานบัญชีของตัวเองหรือเปลี่ยนสิทธิ์ของตัวเอง ป้องกันกรณีเผลอแก้ไฟล์ผิดแล้วล็อกตัวเองออกจากระบบจนไม่มีใครเข้าไปแก้ได้
- ตรวจความถูกต้องของแต่ละแถวก่อนนำเข้า ครอบคลุมชื่อผู้ใช้ที่ต้องยาวอย่างน้อยสามตัวอักษร ชื่อที่แสดงที่ต้องไม่ว่าง สิทธิ์ที่ต้องเป็นค่าที่รู้จัก รหัสหน่วยงานที่ต้องมีอยู่จริง เงื่อนไขว่า Officer และ Supervisor ต้องสังกัดหน่วยงาน และความยาวรหัสผ่านที่ต้องอยู่ระหว่างสิบสองถึงสองร้อยตัวอักษรเท่ากับที่หน้าจัดการผู้ใช้งานใช้อยู่
- เพิ่มรายการหมายเหตุระดับแถวแยกจากรายการข้อผิดพลาด ใช้กับกรณีที่ควรรู้ไว้แต่ไม่ได้ขัดขวางการนำเข้า เช่นบัญชีใหม่ที่ไม่ได้ระบุรหัสผ่านมาแล้วระบบจะสร้างให้ ต่างจากข้อผิดพลาดซึ่งทำให้ทั้งไฟล์ถูกปฏิเสธ
- เมื่อการนำเข้ามีการเปลี่ยนรหัสผ่านหรือปิดใช้งานบัญชีใด ระบบจะยกเลิกเซสชันที่ยังมีผลของบัญชีนั้นทั้งหมดทันทีในทรานแซกชันเดียวกัน ไม่เช่นนั้น token ที่ออกไปก่อนหน้าจะยังใช้งานได้จนกว่าจะหมดอายุ ซึ่งขัดกับเจตนาของการเปลี่ยนรหัสผ่านหรือระงับบัญชี
