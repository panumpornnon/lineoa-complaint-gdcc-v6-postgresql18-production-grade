2026-09-29 (ต่อ) : ย้ายหน่วยงานแล้ว ประวัติต้องยังอยู่กับหน่วยงานเดิม
--------------------------------------------------------------------------------

ปัญหา: สาขา supervisor กรองด้วย c.department_id = $1 ซึ่งเป็นหน่วยงาน "ปัจจุบัน"
ของเรื่องร้องเรียน พอมีการย้ายงานไปหน่วยงานอื่น ประวัติทั้งหมดของเรื่องนั้น
รวมถึงแถวการมอบหมายเอง จะหายไปจากสายตาหน่วยงานเดิมทันที ทั้งที่เป็นงานที่เคยทำจริง

แก้สามจุดควบคู่กัน
1. complaint.assignment.update เก็บ previousDepartmentId และ previousDepartmentName
   เพิ่ม เฉพาะตอนที่ย้ายหน่วยงานจริง (departmentChanged) กรณีเปลี่ยนแค่เจ้าหน้าที่
   ภายในหน่วยงานเดิมจะไม่บันทึก จะได้ไม่มีบรรทัดส่วนเกินขึ้นมารก
   ค้นชื่อทั้งสองหน่วยงานในคิวรีเดียวด้วย id = ANY($1::uuid[])
2. complaint.status.update และ complaint.work_progress.update บันทึก departmentId
   ของงาน ณ ขณะที่ลงมือ ประวัติจึงผูกกับหน่วยงานที่ทำงานจริง ไม่ใช่หน่วยงานปลายทาง
3. เงื่อนไขของ supervisor เปลี่ยนเป็นนับสามทาง
     c.department_id = $1                                   งานอยู่ที่นี่ตอนนี้
     lower(a.detail->>'departmentId') = lower($1::uuid::text)          ตอนลงมืออยู่ที่นี่
     lower(a.detail->>'previousDepartmentId') = lower($1::uuid::text)  ย้ายออกจากที่นี่

บั๊กที่เจอจากการทดสอบ (สำคัญ)
ครั้งแรกเขียนเงื่อนไขเป็น a.detail->>'departmentId' = $1::text ผลคือหน่วยงานเดิม
เห็น 0 แถว สาเหตุคือ $1 ถูกอนุมานชนิดเป็น uuid จากการใช้ครั้งแรกใน c.department_id = $1
พอเขียน $1::text ค่าที่ได้จึงเป็น uuid ที่ถูกแปลงเป็นตัวพิมพ์เล็กตามรูปแบบมาตรฐาน
ซึ่งไม่ตรงกับข้อความใน JSON ที่เทียบแบบตรงตัวอักษร
แก้โดยครอบ lower() ทั้งสองข้าง และแปลงผ่าน $1::uuid::text ให้ได้รูปแบบมาตรฐานเสมอ
เลือกวิธีนี้แทนการ cast ค่าใน JSON เป็น uuid ตรงๆ เพราะถ้าเจอค่าที่ไม่ใช่ uuid
คิวรีจะพังทั้งคำสั่ง ส่วนการเทียบเป็นข้อความแบบไม่สนตัวพิมพ์จะไม่พังไม่ว่าเจอค่าอะไร

หน้าเว็บ
- เพิ่ม previousDepartmentName เป็นบรรทัดแรกของรายละเอียดการมอบหมาย
  ใช้ชื่อว่า "ย้ายมาจากหน่วยงาน" คู่กับ "มอบหมายให้หน่วยงาน"
- ขยายเกณฑ์แสดงเต็มโดยไม่ต้องกางจาก 3 เป็น 4 บรรทัด
- เปลี่ยน ?v= เป็น 20260929-audit-readability-3

ทดสอบกับ PostgreSQL จริง สถานการณ์ย้ายงานจากกองช่างไปกองสาธารณสุข
  หัวหน้ากองช่าง (หน่วยงานเดิม)    เห็น 2 แถว คือแถวที่ตนเคยอัปเดตสถานะ
                                   และแถวมอบหมายที่บอกว่า กองช่าง -> กองสาธารณสุข
  หัวหน้ากองสาธารณสุข (ปลายทาง)    เห็น 3 แถว คือประวัติทั้งหมดของงานที่รับมา
ทดสอบด้วย uuid ที่เขียนเป็นตัวพิมพ์ใหญ่ใน JSON โดยตั้งใจ เพื่อยืนยันว่าเทียบได้จริง

ข้อจำกัดที่เหลือ: แถวที่บันทึกไว้ก่อนการแก้ครั้งนี้ไม่มี departmentId ใน detail
