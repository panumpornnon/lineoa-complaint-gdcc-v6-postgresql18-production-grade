# แผนพัฒนา: หน้ากลางแยกบริการ (Service Hub)

> สถานะ: **แผนสำหรับอนาคต ยังไม่เริ่มพัฒนา**
> บันทึกเมื่อ 10 กันยายน 2569

## ที่มา

ปัจจุบันหน้าประชาชน (`public/index.html`) มีเมนูหลักเพียง 2 แท็บ

```
[ + แจ้งเรื่อง ]  [ ◷ ติดตามเรื่อง ]
```

ทั้งระบบสมมติว่าผู้ใช้เข้ามาเพื่อ "แจ้งเรื่องร้องเรียน" อย่างเดียว ส่วนเรื่อง
ขยะเป็นเพียงหมวดหมู่หนึ่งใน `complaint_categories` (รหัส `WASTE` ชื่อ
"ขยะและความสะอาด" SLA 30 ชั่วโมง)

หากเทศบาลต้องการเพิ่มบริการด้านการกำจัดขยะเป็นบริการแยก เช่น การนัดเก็บ
ขยะชิ้นใหญ่ หรือการดูตารางรถเก็บขยะ จะไม่มีที่ทางให้วางเมนูนั้น

## สิ่งที่ต้องเพิ่ม

### 1. หน้ากลางเลือกบริการ

หน้าแรกที่ผู้ใช้เห็นหลังเปิดจาก LINE OA เปลี่ยนเป็นหน้าเลือกบริการ

```
        เทศบาลนครสุราษฎร์ธานี
   เลือกบริการที่ต้องการใช้งาน

  ┌─────────────────┐  ┌─────────────────┐
  │  แจ้งเรื่อง      │  │  การกำจัดขยะ     │
  │  ร้องเรียน       │  │                 │
  └─────────────────┘  └─────────────────┘
```

เมื่อเลือกแล้วจึงเข้าสู่แท็บย่อยของบริการนั้น (แจ้งเรื่อง / ติดตามเรื่อง)
และต้องมีปุ่มย้อนกลับมาหน้ากลางได้ตลอด

ควรรองรับการเข้าตรงด้วยพารามิเตอร์ เช่น `?service=waste` เพื่อให้ Rich Menu
ของ LINE OA ลิงก์ตรงเข้าบริการใดบริการหนึ่งได้โดยไม่ต้องผ่านหน้ากลาง

### 2. โครงสร้างข้อมูล

มีสองแนวทาง เลือกตามความซับซ้อนของบริการขยะที่จะทำจริง

**แนวทาง ก — ใช้ตาราง `complaints` เดิม เพิ่มคอลัมน์แยกประเภทบริการ**

เหมาะเมื่อบริการขยะมีลักษณะเป็น "คำร้อง" ที่มีสถานะและการมอบหมายเหมือนกัน

- เพิ่ม `service_type` (เช่น `complaint`, `waste`) ในตาราง `complaints`
- หน้าเจ้าหน้าที่กรองตาม `service_type` เพิ่มจากที่กรองตามหน่วยงานอยู่แล้ว
- ใช้ระบบสถานะ SLA รูปภาพ และการแจ้งเตือน LINE เดิมได้ทั้งหมด
- งานน้อยกว่ามาก แต่ถ้าบริการขยะมีฟิลด์เฉพาะเยอะจะทำให้ตารางบวม

**แนวทาง ข — แยกตารางและ API ของบริการขยะออกมา**

เหมาะเมื่อบริการขยะมีข้อมูลเฉพาะทางมาก เช่น วันนัด ประเภทขยะ ปริมาณ ค่าธรรมเนียม

- มีตารางของตัวเอง เช่น `waste_requests`
- แยก route ออกเป็น `src/routes/waste.js`
- ต้องทำระบบสถานะ การมอบหมาย และการแจ้งเตือนใหม่ หรือแยกส่วนที่ใช้ร่วมกัน
  ออกมาเป็น service กลางก่อน

### 3. ฝั่งเจ้าหน้าที่

- เพิ่มตัวกรองประเภทบริการในหน้าเรื่องร้องเรียน
- แดชบอร์ดควรแยกตัวเลขของแต่ละบริการ หรือมีตัวสลับมุมมอง
- รายงาน CSV ต้องมีคอลัมน์ประเภทบริการ
- พิจารณาว่าเจ้าหน้าที่คนเดียวกันดูแลทั้งสองบริการหรือแยกกัน
  ถ้าแยกอาจต้องขยายระบบสิทธิ์

## ผลกระทบต่อของเดิม

| ส่วน | ผลกระทบ |
|---|---|
| Rich Menu ของ LINE OA | ต้องออกแบบใหม่ให้ชี้หน้ากลางหรือชี้ตรงแต่ละบริการ |
| ลิงก์ติดตามเรื่องในข้อความแจ้งเตือน | ต้องพาไปยังบริการที่ถูกต้อง ไม่ใช่หน้ากลาง |
| เรื่องร้องเรียนเดิมในฐานข้อมูล | ต้องเติมค่าประเภทบริการย้อนหลังเป็น `complaint` |
| หมวดหมู่ `WASTE` ที่มีอยู่ | ต้องตัดสินใจว่าคงไว้ในเรื่องร้องเรียน หรือย้ายไปบริการใหม่ |

## ลำดับงานที่แนะนำ

1. สรุปให้ชัดก่อนว่าบริการขยะทำอะไรได้บ้าง (นัดเก็บ / ดูตาราง / ชำระค่าธรรมเนียม)
2. เลือกแนวทาง ก หรือ ข ตามผลข้อ 1
3. ทำหน้ากลางก่อน โดยยังมีบริการเดียวคือเรื่องร้องเรียน เพื่อทดสอบการนำทาง
   และการเข้าตรงด้วยพารามิเตอร์
4. เพิ่ม migration สำหรับประเภทบริการ พร้อมเติมค่าย้อนหลัง
5. พัฒนาบริการขยะ
6. ปรับ Rich Menu และประชาสัมพันธ์

## ข้อควรระวัง

- **อย่าเพิ่งทำหน้ากลางถ้ายังมีบริการเดียว** เพราะจะเพิ่มการกดหนึ่งครั้ง
  โดยไม่ได้ประโยชน์ ควรทำพร้อมกับตอนที่บริการที่สองใกล้เสร็จ
  หรือทำแบบข้ามหน้ากลางอัตโนมัติเมื่อมีบริการเดียว
- ผู้ใช้หลักคือประชาชนทั่วไปที่เปิดจาก LINE บนมือถือ หน้ากลางต้องกดง่าย
  ปุ่มใหญ่ ข้อความสั้น ไม่ควรมีเกิน 4 บริการในหน้าเดียว
- ระบบยังรองรับเฉพาะการแนบรูปภาพ หากบริการขยะต้องแนบเอกสาร
  ต้องแก้ `src/services/uploads.js` ซึ่งอนุญาตเฉพาะ MIME ของรูปภาพ
  และประมวลผลผ่าน sharp
